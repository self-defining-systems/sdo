# Responder command reference

GENERATED by `uv run python -m sdo.agents.responder.command_reference` from the CLI parser, its response definitions and the generated command-report schema. Do not edit by hand.

## Output

Use `--json` before or after the command; for `act`, put SDO options before the wrapped command's `--`. Read commands return the complete JSON response; their default text points to a complete JSON file. Mutations return a compact JSON envelope with `command`, `summary`, `details_file`, `incident_verified` and conditional `error`/`failure_reason`/`hint`. The envelope is limited to 2048 UTF-8 bytes; query `details_file` for complete evidence. The worker provides `jq` for JSON extraction.

Response keys below are conditional: absence is not success or health. Ordinary responses share `command`, `summary`, `healthy`, optional `error` and optional `incident_verified.{verified_at,message}`. Only independent verification establishes recovery. A pending detector reason is unproven health. Closed-incident reads/reports remain available; new mutations are rejected.

Mutation files contain these generated top-level arrays:

- `actions[]`: {command,summary,program_runs,report,option_reports}: complete independent option outputs/receipts; overlapping writes refused
- `findings[]`: {summary,status,detector_id,fingerprint,primary_resource,evidence}: current findings with full evidence
- `fixed[]`: Finding (findings[] shape): absent since the before snapshot
- `new[]`: Finding (findings[] shape): new fingerprint or changed evidence; possible regression
- `option_reports[]`: {status,rounds,attempt_id}: typed per-option execution reports in selection order
- `unchanged[]`: Finding (findings[] shape): same fingerprint and evidence

## mitigate

apply independent options in one call; overlaps refused; shows progress and full JSON

```text
sdo mitigate [-h] [--finding FINGERPRINT] [--rounds ROUNDS] [--selection FILE] [--selection-set FILE] [--option ID] [--param NAME=VALUE] [--match ID] [--bind NAME=REF] [option]
```

Apply several independent options in one call; overlapping object write sets are refused before writes. Use repeated --option ID followed by that option's --param NAME=VALUE, or --selection-set FILE with version 1 and options [{option_id, bindings, parameters, finding_fingerprints}]. --match ID applies a ready playbook_coverage match; --bind narrows it. Each option has its own receipt; one call uses one round. Pending rollout returns its application ID; reads stay open; past its bound it frees its writes as rollout_stalled. A single option also accepts --NAME VALUE parameters. Five rounds per incident. Script fixes are learnable mitigations. Program commands use the current checkout, including shared libraries and new playbook IDs. Edits compile on demand; fix compile errors in place and retry. Revision receipts use working-tree:<source digest> for unpublished code. Reusable API reads use program.Kubernetes(view) with upstream client-go options; reads are recorded for replay.

- `option`: advertised option ID or unambiguous program ID
- `--finding`: target finding fingerprint; repeat for each intended finding
- `--rounds`: maximum rounds within the remaining incident allowance
- `--selection-set`: version 1 selection set with per-option bindings and parameters
- `--option`: independent option ID; repeat, with per-option --param arguments
- `--match`: playbook ID of a ready playbook_coverage match
- `--bind`: with --match: only the match binding NAME to REF (Kind/namespace/name); repeat

```text
Advertised option IDs remain valid for this session across filtered menu calls. Learned program preconditions are rechecked against live state before any batch writes.
```

```text
Parameters accept ordinary JSON objects, arrays, numbers and booleans, as well as strings. sdo menu exports recursive parameters[].schema for every option, plus selection_schema and selection_set_schema; nested properties, required fields and oneOf choices describe accepted shapes. parameters[].example supplies typed synthetic inputs; replace names/values using incident evidence. CLI --param NAME=VALUE accepts JSON text for structured values. SyncWebhookCA privately copies a named Secret key into one webhook caBundle; only its reference and digest are returned. EnsureDatabaseUser repairs a MongoDB user in one call. Its password and target.auth username/password take exactly one credential reference: {env: NAME} or {config_map: {name: CONFIGMAP, key: KEY, assignment: optional_NAME}} in the target Pod namespace. Assignment selects one literal NAME=value line. The executor resolves values privately; never put credential values in arguments, evidence or memory. Direct Secret keys are unavailable. The result reads the catalog back: action_results[].database_user states the verified user and outcome (created, updated or already_correct), and a failure carries a typed failure_reason. A verified user does not mean the application recovered.
```

## act

record one command; outer shell chains run separately; shows progress and a complete JSON report

```text
sdo act [-h] --resource Kind/namespace/name [--summary SUMMARY] [--irreversible] ...
```

Run one live mutation and record its repair receipt (target, resources, timing, outcome and command line). The command's exit code is returned. Do not hand-write receipts. Report one cause per independently fixable fault and record a separate act for each, declaring only that cause's resources, so each receipt is attributed to its cause; combine only faults that can't be fixed separately. When an admission control blocks recovery and its backend is gone, restore the backend if you can. Otherwise a scoped fail-open or removal that restores availability is acceptable; report it. SDO options go before --; the command after it runs verbatim, except that a kubectl command may also carry SDO's --json, --summary and --irreversible, which kubectl never defines. A rejected command line returns a one-line hint with the correct form.

- `--resource`: object the command mutates (Kind/name when cluster-scoped); repeat for each one
- `--summary`: one line describing the repair
- `--irreversible`: the mutation cannot be undone
- `act_command`: the mutating command

```text
Example: sdo act --resource Deployment/app/api -- kubectl -n app set image deployment/api api=img:1.2
```

Complete report fields (`details_file`): `actions[].{success, exit_code, receipt, output, failure_reason, hint}`.

## verify

read cached controller verification; optionally await a stable verdict

```text
sdo verify [-h] [--wait SECONDS]
```

Reads the controller's cached health verdict immediately; drift[] lists objects that still differ from accepted source and never decides healthy. After a healthy return, SDO may resume once for source differences when progress remains; terminal inventory and no-progress stops do not resume. restore them or explain the intended difference. Pending observation windows, including unproven synthetic scenarios, are not healthy. Fresh deployment-rollout-pending findings name owned ReplicaSet/Pod blockers and old-template Pods, including after recorded actions; inspect their evidence before repeating workload writes. Wait on SDO's verification instead of sleeping. After closure, incident_verified is an informational warning on every response; reads and reports remain available, while mutations are rejected. After verified closure, report grace and outcome/reflection work continue during maintenance pauses.

- `--wait`: wait for stable verification, a new/reactivated finding, or this timeout (0: cached and instant)

Key JSON fields: `healthy, unresolved, findings[], detector_states[], drift[], drift_events[]`.
