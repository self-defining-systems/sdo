type ReconcileFromSource struct{ Ref sdk.ObjectRef }
    ReconcileFromSource restores a whole source-owned object to accepted source,
    removing additions SourceDiff reports; prefer SetField for one field.
    An object accepted source declares that is absent is created from source,
    exactly as CreateFromSource (the receipt names the create). For a Secret
    the controller writes the literal data of the accepted render (the keys
    the source declares; other keys stay) and nothing records a value:
    the receipt names the keys. It refuses a Secret whose source has no literal
    data or whose render is not deterministic (a generated password); then
    Escalate. Restart the readers that started after the foreign change with
    RestartRollout later in the same plan, because a running Pod keeps the value
    it started with. Identify readers from their pod template Secret references.
    After it restores a StatefulSet's pod template, each Pod still on another
    revision than status.updateRevision that is failing (ImagePullBackOff,
    ErrImagePull, CrashLoopBackOff) or not Ready past a short bound is deleted,
    one at a time in ordinal order, so the controller recreates it at the
    restored revision; the receipt names each deleted Pod and why.

type RepairData struct {
	Target          StoreTarget
	Scope           DataScope
	Statement       string
	MemberPredicate *MemberPredicate
	CopyFrom        *DataScope
	ExpectMin       int
	ExpectMax       int
	Backup          string
	Reason          string
}
    RepairData runs one write on a scope. Its effect is data-write. It sets
    exactly one of:
      - Statement: a redis single-key write per matched key ("SREM member";
        an argument with spaces is quoted as in redis-cli; only a whole argument
        can be quoted), a mongodb update document or pipeline, a postgres or
        mysql assignment list (SET is optional; a quoted value may hold any
        character), or "delete" (the only memcached statement);
      - MemberPredicate (redis): remove the members it selects from every set,
        sorted set or list the scope matches, for example the members that are
        not digits or whose "post:{member}" key is missing;
      - CopyFrom: copy every item of the CopyFrom scope that Scope's namespace
        lacks into it (a renamed collection, table or key pattern back under its
        name; redis merges sets and sorted sets member by member). Scope names
        the target namespace whole; CopyFrom is left as it is.

    The controller counts the matching items first (the CopyFrom items for a
    copy) and refuses unless the count is within [ExpectMin, ExpectMax], writes
    (atomically with the count on redis, postgres and mysql), then counts Scope
    again and reads the store's facts. Backup optionally names a StoreBackup of
    this incident; the controller records it and whether it covers Scope.
