package traffic // import "sdo.dev/operator/sdk/traffic"

Package traffic is SDO's app-agnostic synthetic-traffic health machinery.

The detection designer writes, in the application's operational memory,
Go generators (.sdo/diagnostics/traffic/generators/) that describe user journeys
as Scenarios: ordered Steps whose Endpoints build requests from a seeded random
source and shared per-iteration State, and check responses. Workload profiles
(.sdo/diagnostics/traffic/workloads/<name>.yaml) say which scenarios run,
how often, and against which SLO.

The Engine owns everything about when and how much: scheduling, arrival,
rate and concurrency caps, timeouts, latency measurement and the random seed
of every iteration, so a failing probe replays exactly. Generators only build
requests and judge responses. The accepted memory host runs the engine; the
controller runtime hands its observations to detectors built with NewDetector,
which judge each scenario against a sliding-window SLO. The default SLO bounds
median (p50) latency. Timeouts contribute to rate violations only when at least
two occur in the window; raw evidence stays visible. The count floor is capped
at the window size, so one-sample windows stay strict. Workload and per-scenario
SLOs may override latencyPercentile, maxLatency and minTimeouts (one opts into
strict timeout sensitivity). Nothing here knows about a particular application,
and nothing calls an LLM.

const DefaultHealthMinDuration = 9 * time.Second
    DefaultHealthMinDuration is how long a health (Class health) traffic
    detector's failing samples must span, from the first failing
    sample in the window to the last, before a scenario violation is
    reported, when its spec leaves Persistence.MinDuration unset.
    Synthetic-traffic windows are re-evaluated on every probe poll
    (sdo/operator/runtime.DefaultTrafficPollInterval, 500ms), so an
    evaluation-count-only policy reaches its firing threshold in about 0.5s.
    A kind worker's data plane can stall for about 3s after a pod-network change
    (roughly 1 in 6-10 such changes), producing real prober timeouts that would
    otherwise dispatch a responder for nothing. Real faults in this suite are
    detected in 3-5s. Nine seconds clears the observed stalls with headroom
    while adding at most one more poll beyond real-fault detection.

FUNCTIONS

func BuildHTTPRequest(ctx context.Context, baseURL string, request Request) (*http.Request, error)
    BuildHTTPRequest renders request against baseURL (scheme://host:port) with a
    canonical, sorted query string and the synthetic marker header.

func CheckCatalog(ctx context.Context, catalog Catalog) []error
    CheckCatalog validates the catalog and checks every scenario detects its
    required and declared fault classes. Generated tests call it so a generator
    that cannot tell a broken application from a healthy one never reaches the
    controller.

func CheckDetects(ctx context.Context, scenario Scenario, class FaultClass) error
    CheckDetects runs scenario once against a simulated fault of class and
    returns an error unless the scenario fails the way a probe must: with an
    error or timeout, not by being unable to build its requests.

func DefaultLatencyNote(id string) string
    DefaultLatencyNote is the non-blocking memory-check note for a scenario
    DefaultLatencyScenarios returns.

func DefaultLatencyScenarios(workloads []Workload) []string
    DefaultLatencyScenarios returns, sorted, the scenarios of health-probe
    workloads whose effective SLO keeps DefaultMaxLatency. The default bound
    is generous so that any application starts green; a saturated service
    often slows its path many times over long before it fails, and a read that
    normally takes tens of milliseconds can stay under the default while its
    service is pinned at its CPU limit. Each scenario returned is a critical
    path whose slowdown health cannot see.

func FailingUserScenarios(ctx sdk.DetectionContext) []string
    FailingUserScenarios lists, as "workload/scenario" sorted, every qualified
    health-probe scenario of the context's carried windows that violates its SLO
    now: the user-facing failures a cause-only detector may gate on. It is empty
    when the context carries no traffic.

func FromSeedPair(key string, count int, first func(index int) string, second func(index int) string) (Param, Param)
    FromSeedPair returns two parameters rendered from the same seeded record,
    such as a user name and its password. The record index is kept in State
    under key, so later steps can reuse it with FromPrevious.

func KnownBrokenChanges(window Window) string
    KnownBrokenChanges describes the KnownBroken scenarios of window whose state
    changed from their declaration: one that now meets its SLO, or one whose
    recent failures include a status key outside FailsWith. It is empty when
    every KnownBroken scenario still fails as declared or has too few samples to
    judge. It is a note for the detection designer, never a finding.

func LinkFinding(spec sdk.DetectorSpec, namespace string, window Window, observed LinkObservations) (sdk.Finding, bool)
    LinkFinding explains one link JudgeLink reports, with per-link p50/p95
    latency and failure classes. The primary resource is the target Service;
    the calling Service is related.
