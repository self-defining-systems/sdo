	Condition LinkCondition

	Consecutive int

	// Shared is the median slowdown (recent median over baseline) of the
	// link's peers, at least 1.
	Baseline time.Duration
	Spread   time.Duration
	Shared   float64
	Bound    time.Duration

func JudgeLink(window Window, observed LinkObservations) (LinkJudgement, bool)
    JudgeLink reports a qualified link whose fresh dials show it unreachable
    (LinkFailing), intermittent (at least LinkLossPercent of the last
    LinkLossWindow dials failed, consecutive or not) or slow. Slow needs each
    of the last LinkSlowWindows windows of Failures dials to have a median
    above the bound: LinkLatencyFactor times the baseline, the baseline plus
    LinkSpreadFactor times its spread, and MinLinkLatencyBound, where baseline
    and spread are first multiplied by the slowdown the link's peers (the
    setting's Peers) share. A loaded prober node slows every dial alike, so it
    never makes one link slow. A stalled host (HostStallBound) explains dial
    timeouts and slowness everywhere at once, even where the peers stay fast:
    slowness is not judged while any judged dial was made on a stalled host,
    its timeouts do not count toward intermittent, and a run of them is
    unreachable only once it fills LinkLossWindow dials. Refusals, resets and
    protocol failures are judged as usual. Only recent samples are judged:
    the slow and loss windows reach back at most the larger of MaxAge and twice
    their length in probe periods.

type ProbeUser struct {
	Name   string `json:"name"`
	As     string `json:"as"`
	SSHKey string `json:"sshKey,omitempty"`
}
    ProbeUser names a test user a scenario signs in as. SDO provisions the
    user through the application's own identity procedure (the application
    map's procedure marked probe_identity) with a password SDO generates;
    nothing is read from an application Secret. The engine puts the password in
    each iteration's State under As, so a setup step signs in with "{As}" in a
    header, path, query, form or JSON body, or with WithBasicAuth, and saves
    the session or token the steps send. Name contains the scenario's Marker.
    Operational memory and agents hold the name, never the password, and no
    sample carries it.

    SSHKey, when set, names the State key under which the engine puts the
    user's SSH public key as an authorized-keys line ("ssh-ed25519 AAAA..."),
    so a setup step registers it with the application ("{SSHKey}"). SDO derives
    the key pair from the same seed as the password, so it is the same on every
    host and after a restart; register it with OrExisting. The private key never
    leaves the prober: it signs the scenario's ssh steps, at most one user per
    scenario sets SSHKey, and a scenario with an ssh step needs one.
