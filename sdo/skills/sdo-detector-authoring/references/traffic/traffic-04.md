type Passwords interface {
	Password(ctx context.Context, user string) (string, error)
}
    Passwords returns the password of a provisioned probe user. An error
    means the user cannot be used yet (provisioning is pending or failed);
    the iteration is then invalid and sends nothing.

type ProbeKeys interface {
	SSHPublicKey(ctx context.Context, user string) (string, error)
}
    ProbeKeys returns the SSH public key line of a provisioned probe user.
    A Passwords source that also implements ProbeKeys serves scenarios whose
    users declare SSHKey; an error means the user cannot be used yet.

type ProbeUser struct {
	Name   string `json:"name"`
	As     string `json:"as"`
	SSHKey string `json:"sshKey,omitempty"`
}
    ProbeUser names a test user a scenario signs in as. SDO provisions the
    user through the application's own identity procedure (the application
    map's procedure marked probe_identity) with a password SDO generates;
    nothing is read from an application Secret. The engine puts the password in
    each iteration's State under As, so a setup step signs in with "{As}" in a
    header, path, query, form or JSON body, or with WithBasicAuth, and saves
    the session or token the steps send. Name contains the scenario's Marker.
    Operational memory and agents hold the name, never the password, and no
    sample carries it.

    SSHKey, when set, names the State key under which the engine puts the
    user's SSH public key as an authorized-keys line ("ssh-ed25519 AAAA..."),
    so a setup step registers it with the application ("{SSHKey}"). SDO derives
    the key pair from the same seed as the password, so it is the same on every
    host and after a restart; register it with OrExisting. The private key never
    leaves the prober: it signs the scenario's ssh steps, at most one user per
    scenario sets SSHKey, and a scenario with an ssh step needs one.

type SLO struct {
	Window         int      `json:"window,omitempty"`
	MinSamples     int      `json:"minSamples,omitempty"`
	MaxAge         Duration `json:"maxAge,omitempty"`
	MaxErrorRate   float64  `json:"maxErrorRate,omitempty"`
	MaxTimeoutRate float64  `json:"maxTimeoutRate,omitempty"`
	// MinTimeouts is the minimum timeout count before timeouts contribute to
	// either rate violation. Defaults to two so one scheduling pause is noise.
	// The effective floor is capped at Window so a total timeout outage fires.
	// Set one explicitly for strict timeout objectives.
	MinTimeouts       int      `json:"minTimeouts,omitempty"`
	LatencyPercentile int      `json:"latencyPercentile,omitempty"`
	MaxLatency        Duration `json:"maxLatency,omitempty"`
}
    SLO bounds a scenario's recent behaviour. Zero fields inherit the workload's
    SLO, and then the package defaults. The default latency bound applies to
    the median; one timeout remains evidence but does not contribute to rate
    violations until MinTimeouts is reached.

func Evaluate(scenarioID string, slo SLO, samples []Sample, now time.Time) SLOVerdict
    Evaluate judges samples (oldest first) of one scenario at now. Invalid
    samples and samples older than the SLO's maxAge are ignored, only the
    latest window samples count, and fewer than minSamples leaves the scenario
    unevaluated, which is healthy.

func Judge(window Window) []SLOVerdict
