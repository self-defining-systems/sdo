type PersistencePolicy struct {
	Firing   int
	Clearing int
	// MinDuration, when positive, additionally requires a finding to have
	// been continuously observed for at least this long before it fires.
	// A finding that reaches Firing evaluations sooner stays pending until
	// MinDuration also elapses, then activates on its next observation. Zero
	// keeps the evaluation-count-only policy. This absorbs findings whose
	// evaluation count crosses the firing threshold within one brief stall
	// (for example a synthetic-traffic window re-evaluated on every poll),
	// while a persistent fault still fires once both conditions hold.
	MinDuration time.Duration
}

    PlatformObservation freezes, once per evaluation, the platform policy
    that governs the application namespace and is usually not declared by the
    application's source: the Namespace's labels and annotations (Pod Security
    levels among them), its LimitRanges, ResourceQuotas (with usage), Roles
    and RoleBindings, every admission webhook entry that selects Pods in it,

    accepted source inventory. A part that could not be read is absent and named
    in Errors; its accessor returns that error, never an empty list.

    baseline (nil until the application has been healthy once); Changes lists
    what differs from it.

type PodAdmissionResult struct {
	Namespace string `json:"namespace"`
	SourcePod string `json:"source_pod,omitempty"`
	Admitted  bool   `json:"admitted"`
	Rejection string `json:"rejection,omitempty"`
	Error     string `json:"error,omitempty"`
	// Latency is how long the API server took to answer the dry-run create,
	// admission webhooks included; a webhook that hangs shows here.
	Latency time.Duration `json:"latency_ns,omitempty"`
	// Mutations are the fields admission changed in the admitted Pod compared
	// with the Pod submitted, excluding values the API server fills in by
	// default (pull policy, termination message, service account token volume,
	// default tolerations and the like). Webhooks and built-in admission such
	// as a LimitRange both mutate; Webhooks names the candidates.
	Mutations []FieldChange `json:"mutations,omitempty"`
	// Webhooks are the admission webhook entries whose rules, namespaceSelector
	// and objectSelector select the submitted Pod, so the entries that took
	// part in its admission. With Mutations and a single mutating entry, the
	// mutation is attributed exactly.
	Webhooks []AdmissionWebhook `json:"webhooks,omitempty"`
}
    PodAdmissionResult freezes one server-side dry-run Pod create. Rejection
    contains an API failure; Error means the observation itself was unavailable.
    No Pod is persisted and no referenced Secret is read by the observer.

    The dry-run Pod is built from the pod template of the source Pod's
    controller (its ReplicaSet, StatefulSet or DaemonSet) when the snapshot
    holds it, so Mutations shows what admission changes in a Pod the workload
    would create now, not what an earlier admission already wrote into a running
    Pod.
