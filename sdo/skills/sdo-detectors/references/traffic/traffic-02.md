FUNCTIONS

func BuildHTTPRequest(ctx context.Context, baseURL string, request Request) (*http.Request, error)
    BuildHTTPRequest renders request against baseURL (scheme://host:port) with a
    canonical, sorted query string and the synthetic marker header.

func CheckCatalog(ctx context.Context, catalog Catalog) []error
    CheckCatalog validates the catalog and checks every scenario detects its
    required and declared fault classes. Generated tests call it so a generator
    that cannot tell a broken application from a healthy one never reaches the
    controller.

func CheckDetects(ctx context.Context, scenario Scenario, class FaultClass) error
    CheckDetects runs scenario once against a simulated fault of class and
    returns an error unless the scenario fails the way a probe must: with an
    error or timeout, not by being unable to build its requests.

func CheckProbeLoad(workloads []Workload, catalog Catalog) error
    CheckProbeLoad rejects a health-probe set whose floor load exceeds
    ProbeRateCap requests per second: the load of sampling every scenario once
    per sample interval, at the lowest rate that does so (a workload's own or
    default rate above that is not counted, since an unset rate is the default
    and the designer did not choose it). Each scenario's steps come from the
    catalog (one when it is absent). The check is deterministic, so the memory
    check refuses a set no choice of rate could bring under the cap.

func ConfirmedFailures(windows map[string]Window) map[string]string
    ConfirmedFailures are the scenarios whose failure needs no further samples,
    as "workload/scenario" to the reason: failing samples with no success
    between them, or of two user tests ending within confirmPeerWindow,
    that began at least confirmStallSpan apart. Only qualified, evaluated
    health-probe scenarios that are not KnownBroken count. One failing sample
    never confirms itself, and a partial failure is left to the SLO.

func DefaultLatencyNote(id string) string
    DefaultLatencyNote is the non-blocking memory-check note for a scenario
    DefaultLatencyScenarios returns.

func DefaultLatencyScenarios(workloads []Workload) []string
    DefaultLatencyScenarios returns, sorted, the scenarios of health-probe
    workloads whose effective SLO keeps DefaultMaxLatency. The default bound
    is generous so that any application starts green; a saturated service
    often slows its path many times over long before it fails, and a read that
    normally takes tens of milliseconds can stay under the default while its
    service is pinned at its CPU limit. Each scenario returned is a critical
    path whose slowdown health cannot see.

func FailingUserScenarios(ctx sdk.DetectionContext) []string
    FailingUserScenarios lists, as "workload/scenario" sorted, every qualified
    health-probe scenario of the context's carried windows that violates its SLO
    now: the user-facing failures a cause-only detector may gate on. It is empty
    when the context carries no traffic.

func FromSeedPair(key string, count int, first func(index int) string, second func(index int) string) (Param, Param)
    FromSeedPair returns two parameters rendered from the same seeded record,
    such as a user name and its password. The record index is kept in State
    under key, so later steps can reuse it with FromPrevious.

func KnownBrokenChanges(window Window) string
    KnownBrokenChanges describes the KnownBroken scenarios of window whose state
    changed from their declaration: one that now meets its SLO, or one whose
    recent failures include a status key outside FailsWith. It is empty when
    every KnownBroken scenario still fails as declared or has too few samples to
    judge. It is a note for the detection designer, never a finding.

func LinkFinding(spec sdk.DetectorSpec, namespace string, window Window, observed LinkObservations) (sdk.Finding, bool)
    LinkFinding explains one link JudgeLink reports, with per-link p50/p95
    latency and failure classes. The primary resource is the target Service;
    the calling Service is related.

func LinkFindingIn(spec sdk.DetectorSpec, namespace string, setting LinkSetting, observed LinkObservations) (sdk.Finding, bool)
    LinkFindingIn explains a link JudgeLinkIn reports. A client-vantage finding
    has its own rule ID (the prober's with a ".client" suffix) and names the
    client Pod, so it stands next to the prober's judgement of the same edge:
    slow from the client while fast from the prober places the impairment on the
    client's egress.

func NewDetector(spec sdk.DetectorSpec, workload string) sdk.Detector
    NewDetector returns a health detector that reports every qualified scenario
    of a health-probe workload that violates its SLO. It decides purely from
    the prober's observed samples; missing or unproven observations remain
    unconfirmed and cannot establish health. A health-class spec that leaves
    Persistence.MinDuration unset reports a failure once it is confirmed
    (ConfirmedFailures: it spans 4s with no success between), and any other SLO
    violation (a partial failure, high latency) once its failing samples span
    DefaultHealthMinDuration, counted from the first failing sample. A spec that
    sets MinDuration has only the SLO and its own duration.

func NewLinkDetector(spec sdk.DetectorSpec, workload string) sdk.Detector
    NewLinkDetector returns a health detector that reports every qualified link
    of a link-probe workload that JudgeLink finds unreachable, intermittent or
    slow. It decides purely from the prober's samples; with no observations it
    reports nothing. The sample counts are the hysteresis, so unlike NewDetector
    it does not add DefaultHealthMinDuration. Unreachable and intermittent links
    are critical; a slow link still serves, so it is a warning: batch warnings
    for slow links to open incidents.

func ScenarioFinding(spec sdk.DetectorSpec, namespace string, workload Workload, scenario Descriptor, verdict SLOVerdict) sdk.Finding
    ScenarioFinding explains one unhealthy scenario. The primary resource is
    the Service the scenario calls; the Services it depends on are related,
    so the finding localizes the fault along the request path.

func ScenarioSLOWorkload(detector sdk.Detector) string
    ScenarioSLOWorkload returns the workload whose scenario SLO violations this
    detector reports, or an empty string for other detectors, including links.

func StartsFailing(observed ScenarioObservations, slo SLO, now time.Time) bool
    StartsFailing reports whether a qualified scenario's newest usable sample
    failed right after a success, so it is worth sampling again now.

type Catalog []Scenario
    Catalog is the set of scenarios an application's generators provide.

func CompleteCatalog(catalog Catalog, paths map[string][][]string) Catalog
    CompleteCatalog fills what Go derives instead of the author: an empty
    SideEffect from the steps' methods (InferSideEffect), and an empty DependsOn
    from paths, the Services of each component on the operations' paths of the
    application map's probe line for the scenario. DependsOn gets one Service
    per component: the one the scenario's steps call, else the component's
    first. Scenarios whose side effect cannot be inferred keep it empty,
    and Validate says what to declare. The generated catalog runs every scenario
    through it, so the prober, the checks and the controller see the same
    values.

func (c Catalog) Scenario(id string) (Scenario, bool)
    Scenario returns the scenario with the given ID.

func (c Catalog) Validate() error
    Validate validates every scenario and rejects duplicate IDs.

type DetectionEstimate struct {
	// Every is the mean time between the scenario's scheduled samples.
	Every time.Duration
	// Typical is for a failure at a random moment whose requests fail about
	// as fast as a healthy run.
	Typical time.Duration
	// Worst is for a failure at the worst moment of the schedule whose
	// requests hang until the request timeout.
	Worst time.Duration
}
    DetectionEstimate is how long a health probe takes to notice a scenario
    whose every request starts failing, through the fast confirmation path
    (ConfirmedFailures). It is computed from the workload's own schedule and
    SDO's confirmation rules, never measured.
