func (s Scenario) Validate() error
    Validate reports the first problem that makes the scenario unsafe or
    ambiguous. Rules that depend on built requests (read scenarios send only
    GET/HEAD; writes carry the marker) are enforced by the engine per request;
    a declarative HTTPEndpoint step of a read scenario is also checked here.

type ScenarioObservations struct {
	Scenario Descriptor `json:"scenario"`
	Samples  []Sample   `json:"samples"`
	// Qualified reports whether the scenario has succeeded at least once
	// since observation began. A scenario that never succeeded is not a
	// firing health signal: its generator may not match this deployment.
	// It remains unproven and must not establish confirmed health.
	Qualified bool `json:"qualified"`

	// safety rule; LastInvalid explains the latest one.

	Defect  string `json:"defect,omitempty"`

type SetupLocker interface {
	Lock(ctx context.Context, key string) (release func(), err error)
}
    SetupLocker serializes a setup request across probe processes (a hot-swapped
    memory host overlaps its predecessor, a restart replays setup). key names
    the request, not the scenario, so every scenario and process that would
    write the same fixture waits for the others. The in-process lock is always
    held too.

type SideEffect string
    SideEffect classifies what a scenario does to application state.

const (
	// SideEffectRead scenarios send only GET and HEAD requests.
	SideEffectRead SideEffect = "read"
	// SideEffectIdempotentWrite scenarios write the same dedicated synthetic
	// data every time, so repeating them changes nothing further.
	SideEffectIdempotentWrite SideEffect = "idempotent-write"
	// SideEffectWriteWithCleanup scenarios create synthetic data and remove
	// it again with their Cleanup steps.
	SideEffectWriteWithCleanup SideEffect = "write-with-cleanup"
)
type Source interface {
	TrafficWindow(workload string) (Window, bool)
}
    Source is implemented by detection contexts that carry synthetic-traffic

type State map[string]string
    State carries values between the steps of one iteration, for example an
    ID a create step saved for the read and cleanup steps that follow. Every
    iteration starts with State holding only the engine's own keys (StateNow and
    the probe users' credentials).

type Step struct {
	Name     string
	Endpoint Endpoint
	Target   *Target
}
    Step is one named request of a scenario. Target, when set, overrides the
    scenario's target for this step, so one journey can, for example, register a
    key over HTTP and then use it over SSH. Its Service must be the scenario's
    target or one of its DependsOn.

type Target struct {
	Service string `json:"service"`
	Port    int    `json:"port"`
	Scheme  string `json:"scheme,omitempty"`
	User    string `json:"user,omitempty"`
}
    Target is the Service, in the application namespace, a scenario calls.
    Scheme is "http" (the default), "https" or "ssh"; User is the SSH login name
    and is set exactly when Scheme is "ssh".

type Verdict struct {
	OK     bool
	Reason string
	// Pending marks "not yet": the effect the step looks for may still arrive.
	// The engine then re-Builds and re-sends the step until it passes, fails
	// (a Verdict that is neither OK nor Pending), or the iteration timeout
	// passes, which fails the step with the last Reason. A pending verdict
	// outside Steps (setup, cleanup) is a failure.
	Pending bool
}
    Verdict is an Endpoint's judgement of one response.

func Fail(format string, args ...any) Verdict
    Fail rejects a response with a reason that names what was wrong.

func NotYet(format string, args ...any) Verdict
    NotYet is a pending verdict; see Verdict.Pending. Only a read should return
    it: the step is sent again.

func Pass() Verdict
    Pass accepts a response.

func (w Window) ExistingRecordsExercised() int
    ExistingRecordsExercised counts the samples in which a ReadsExistingRecords
    step returned at least one record the probe did not write.

func (w Window) IdentityWait() time.Duration
    IdentityWait is the longest provisioning run any scenario is still waiting
    for, zero when none waits on a probe user.

func (w Window) LinkSetting() LinkSetting
    LinkSetting returns the setting of the window's link-probe workload.

func (w Window) Ready() bool
    Ready reports whether the window holds what its own detectors need to judge
    it: every observed scenario has the usable samples its SLO requires (failed
    samples count, so an outage is judged rather than waited out), and every
    link has a sample. The traffic detector's ConfirmationReason is built on the
    same predicate, so a ready window can differ from a confirmed one only by
    scenarios that have not yet succeeded.

func (w Window) SLO() SLO
    SLO returns the workload's effective SLO, defaults included.

func (w Window) WarmupHorizon() time.Duration
    WarmupHorizon is how long a freshly started prober needs, at the workload's
    rate, to give every scenario its SLO's minimum samples.

type WindowSet interface {
	TrafficWindows() map[string]Window
}
    WindowSet lists every window a source carries, so a capture of the detection
    context keeps them for replay. Every program.ReadView, the controller's
    live view, the memory host's view and recorded snapshots implement it;
    a source without traffic returns an empty map.

func ParseWorkloadJSON(data []byte) (Workload, error)
    ParseWorkloadJSON strictly decodes a workload, applies defaults, and
    validates it on its own; ValidateAgainst checks it against a catalog.

func (w Workload) DetectionHorizon() time.Duration
    DetectionHorizon is the longest time a health-probe workload can take,
    from the moment a component its scenarios use stops answering, to raise a
    failing scenario: the requests that began before the break must time out,
    the SLO window must hold enough failed samples (at the scenario's arrival
    rate) for the verdict, the failures must span the hold, and the detector
    must confirm the violation on consecutive evaluations. A check that waits
    for a raise must wait at least this long, or a probe that works reads as one
    that does not. It is zero for a workload that is not a health probe.

func (w Workload) KnownBrokenScenario(id string) *KnownBroken
    KnownBrokenScenario returns the KnownBroken declaration of scenario id,
    or nil when the scenario gates health.

func (w Workload) SamplingPlan() SamplingPlan
    SamplingPlan builds the workload's plan. A health probe samples every
    scenario at least once per MinSampleInterval regardless of weight: each
    cycle starts with one iteration of every scenario, and the iterations the
    workload's rate leaves over in that interval are shared by weight. When the
    rate cannot cover every scenario once per interval it is raised to do so.
    Other workloads (bursts, journeys) follow their weights only.

func (w Workload) ScenarioArrival(id string) time.Duration
    ScenarioArrival is the expected time between samples of one scenario under
    the workload's SamplingPlan. Zero when the rate or the scenario is unknown.

func (w Workload) ScenarioSLO(id string) SLO
    ScenarioSLO is the effective SLO of one scenario of the workload.

func (w Workload) Validate() error
    Validate reports the first problem that makes the workload unsafe.

func (w Workload) ValidateAgainst(catalog Catalog) error
    ValidateAgainst checks that every scenario the workload names exists in the
    catalog. A health probe may hold only write scenarios.

func (w Workload) WithDefaults() Workload
    WithDefaults fills unset fields.
