type Engine struct {
	// Has unexported fields.
}
    Engine runs one workload's scenarios. It alone decides which scenario an
    iteration runs, seeds its random source, bounds its time, and measures it.

func NewEngine(workload Workload, catalog Catalog, client Doer, baseURL func(Target) string, clock Clock) (*Engine, error)
    NewEngine validates workload against catalog and prepares its schedule.
    baseURL maps a scenario target to scheme://host:port.

func (e *Engine) Descriptors() []Descriptor
    Descriptors describe the workload's scenarios in workload order.

func (e *Engine) Iterate(ctx context.Context, iteration uint64) (string, Sample)
    Iterate runs iteration once and never returns an error: every failure is a
    sample. A scenario's setup steps run first until each has succeeded once
    in this engine (or an engine it shares setup with); a retry resumes at the
    first step that has not succeeded. A failed setup step fails the sample, and
    setup time is not part of its latency. Cleanup steps of a write-with-cleanup
    scenario run after any request was sent, even when a step failed; their
    failures are reported in CleanupError and do not change the outcome.

    A writing scenario's iteration first waits until no other iteration of this
    engine, or of one it shares setup with, is acting on the same synthetic
    identity (the same requests, or the same probe user): its read-back must
    see its own write, not one a concurrent sample made in between. The wait is
    before the sample starts, so it is not part of the sample's time or latency.

func (e *Engine) IterateWithTrace(ctx context.Context, iteration uint64, trace func(step string)) (_ string, result Sample)
    IterateWithTrace runs the same iteration as Iterate. When trace is set it
    receives the name of every attempted setup, journey, and cleanup step,
    in order. It receives no request, response, or state values.

func (e *Engine) IterationOf(scenario string, from uint64) (uint64, bool)
    IterationOf is the first iteration at or after from that runs scenario:
    the request the schedule would send for it, so running it now repeats a
    scheduled request. ok is false for a scenario the workload does not run.

func (e *Engine) Plan(ctx context.Context, iteration uint64) ([]Request, error)
    Plan builds, without sending, the requests of iteration assuming every step
    succeeds without saving state, as if it started now. It is meant for review;
    replay uses PlanAt with the failing sample's At.

func (e *Engine) PlanAt(ctx context.Context, iteration uint64, at time.Time) ([]Request, error)
    PlanAt is Plan for an iteration that started at at (a sample's At), so the
    requests that depend on the iteration's time are the ones it sent.

func (e *Engine) Rand(iteration uint64) *rand.Rand
    Rand is the random source of iteration: within one engine the same iteration
    always yields the same values, so a failing probe replays, and distinct
    iterations yield distinct ones. The engine's run nonce is part of the
    source, so a restarted prober (whose iterations count from 0 again) draws
    different values than the run before it.

func (e *Engine) Rate() float64
    Rate is the iterations per second the engine starts: the workload's rate,
    raised when its scenarios' sampling floor needs more.

func (e *Engine) Run(ctx context.Context, first uint64, emit func(scenario string, sample Sample)) (uint64, int)
    Run starts iterations at the workload's arrival pattern and rate,
    from iteration first, until ctx ends or, for bounded workloads, the duration
    elapses. At most MaxInFlight iterations run at once; an arrival that finds
    them all busy is skipped. A scheduled sample that begins a failure is
    confirmed by at most two more (UseConfirm). It waits for running iterations
    and returns the next iteration number and the number of skipped arrivals.

func (e *Engine) ScenarioAt(iteration uint64) Scenario
    ScenarioAt is the scenario iteration runs. The choice depends only on the
    iteration number: it follows the workload's SamplingPlan, which gives every
    scenario of a health probe its floor and shares the rest by weight.

func (e *Engine) ShareSetup(source *Engine)
    ShareSetup makes e use source's record of completed setup steps, so a setup
    step that succeeded in either engine is never run again by the other,
    source's rate-limit waits, so neither sends while the application asked the
    other to wait, and source's identity locks, so a writing sample of either
    engine never overlaps one of the other that acts on the same synthetic
    identity (Iterate). A process that runs the same catalog in several engines
    (a continuous probe and its verify bursts) shares one record: data a setup
    step wrote and that was lost afterwards then fails every engine instead of
    being written again. Both engines must run the same catalog.

func (e *Engine) UseConfirm(startsFailing func(scenario string) bool, record func(scenario string, sample Sample))
    UseConfirm makes Run sample a scenario again when startsFailing says its
    scheduled sample began a failure (StartsFailing), and hands those samples to
    record instead of Run's emit.

func (e *Engine) UseExec(execer Execer)
    UseExec lets scenarios run EXEC steps on ssh targets through execer.
    An engine without one records such steps as invalid.

func (e *Engine) UseNonce(nonce uint64)
    UseNonce fixes the run nonce, for tests that need values reproducible across
    engines. Production engines keep the random nonce NewEngine draws.

func (e *Engine) UsePasswords(source Passwords)
    UsePasswords lets scenarios that declare Users sign in with the passwords
    source returns. A prober gives every engine the same source.

func (e *Engine) UseSetupLock(l SetupLocker)
    UseSetupLock makes e serialize each setup request across processes with l.

func (e *Engine) UseWarmup(warming func() bool)
    UseWarmup makes Run pace iterations at the workload's WarmupRate while
    warming reports true, and at Rate otherwise. The caller owns the predicate:
    a prober warms up from its start or reset until every scenario holds its
    SLO's minimum samples.

func (e *Engine) Workload() Workload
    Workload returns the engine's workload with defaults applied.

type Exec struct {
	// Address is host:port of the target Service.
	Address string
	// Login is the target's SSH User.
	Login     string
	ProbeUser string
	Command   string
	Stdin     string
}
    Exec is one command the engine asks the prober's SSH transport to run.
    ProbeUser names the probe user whose key signs the session; the engine never
    holds the private key.

type ExecResult struct {
	Exit   int
	Stdout []byte
	Stderr string
}
    ExecResult is a finished command: its exit status, standard output (at most
    MaxResponseBody bytes) and standard error (at most MaxExecStderr bytes).

type Execer interface {
	Exec(ctx context.Context, exec Exec) (ExecResult, error)
}
    Execer runs EXEC requests over SSH; the prober supplies it, like the HTTP
    Doer. A failure to connect returns the dial error (a *net.OpError with
    Op "dial"), a deadline returns an error wrapping the context's error,
    and a session that ends without an exit status is an error.

type ExistingRecordsStep struct {

	// OwnKeys are the State keys the step templates (in its path, query,

	// step then reads what the scenario itself wrote.
	OwnKeys []string

    ExistingRecordsStep is the compiled fact about one step built with

type FailureMatch struct {
	ScenarioID string
	PatternID  string
	Sample     Sample
}
    FailureMatch is one recent failing sample whose Error matched a pattern.

func MatchFailures(window Window, patterns ...logs.Pattern) ([]FailureMatch, error)
    MatchFailures returns the recent failing samples of window's qualified
    scenarios whose Error matches a pattern, scenario by scenario, oldest first,
    one match per sample and pattern. It sees the same recent samples Judge does
    (usable, within the SLO's age and window), so a cause-specific detector
    keys on the exact failure text instead of searching a finding's Evidence.
    Patterns are RE2 and use the same ID and size rules as log patterns;
    a malformed pattern is an error, never a non-match.

type FaultClass string
    FaultClass is a failure a scenario must detect. Every scenario must detect
    FaultUnreachable and FaultErrorStatus; the others are declared when the
    scenario's checks are strong enough to catch them.

const (
	// FaultUnreachable: the target refuses connections or does not resolve.
	FaultUnreachable FaultClass = "unreachable"
	// FaultErrorStatus: the target answers with a 5xx status, or an EXEC
	// exits non-zero.
	FaultErrorStatus FaultClass = "error-status"
	// FaultWrongBody: the target answers 200 with an empty or wrong body.
	FaultWrongBody FaultClass = "wrong-body"
	// FaultSlow: the target does not answer within the request timeout.
	FaultSlow FaultClass = "slow"
)
