type SLO struct {

    Evaluate judges samples (oldest first) of one scenario at now. Invalid

type Scenario struct {
	ID          string
	Description string
	Target      Target
	DependsOn   []string
	SideEffect  SideEffect
	Marker      string
	Setup       []Step
	Steps       []Step
	Cleanup     []Step
	Detects     []FaultClass
	// Users are the probe users the scenario signs in as; see ProbeUser.
	Users []ProbeUser
}
    Scenario is one user journey. DependsOn names the Services on its request
    path, as described in .sdo/arch.md, so a failing scenario localizes the
    fault. Writes must use dedicated synthetic data whose Marker appears in
    every write request.

    Setup steps create the scenario's own test data (a test identity,
    a fixture a later read must find) so the scenario never depends on data set
    up by hand. The engine runs them at the start of the first iterations until
    each has succeeded once; a retry resumes at the first step that has not
    succeeded, with the State the earlier ones saved, so a step that succeeded
    (one that created a credential, say) is not repeated when a later one fails.
    Data lost afterwards then fails the Steps instead of being written again,
    also in the controller's verify bursts, which share the continuous probe's
    setup. Setup requests may write in any scenario and must carry the Marker;
    make them idempotent (OrExisting) because a restarted prober runs them
    again. Values they save are visible to every iteration.

func (s Scenario) Describe() Descriptor
    Describe returns the scenario's descriptor with its effective fault classes.

func (s Scenario) ExistingRecordsSteps() []ExistingRecordsStep
    ExistingRecordsSteps reports the scenario's steps marked with
    ReadsExistingRecords. To find the keys a marked step templates, it builds
    the step's request with every key a step saves set to a distinct sentinel
    and looks for the sentinels in the request, so it holds for any parameter
    generator.

func (s Scenario) FaultClasses() []FaultClass
    FaultClasses returns the required classes followed by the declared ones.

func (s Scenario) StatusOnly() bool
    StatusOnly reports whether every step (setup excluded) is a declarative
    HTTPEndpoint that checks nothing but the status, so the scenario cannot tell
    a wrong or empty answer from a correct one.

func (s Scenario) Validate() error
    Validate reports the first problem that makes the scenario unsafe or
    ambiguous. Rules that depend on built requests (read scenarios send only
    GET/HEAD; writes carry the marker) are enforced by the engine per request;
    a declarative HTTPEndpoint step of a read scenario is also checked here.
