## Incident result ownership

Return only the agent-owned fields in the session output schema: `incident_id`, `status`, `confirmed_root_causes`, `applied_playbooks`, `repair_changes`, `verification_evidence`, `timing`, `drift_events`. Controller-owned fields, including drift counts, are derived independently. Contract validation feedback permits one correction in the same session; preserve completed repairs. Receipts and controller facts are never model-authored.

## Mitigation menu and responder continuity

The menu is a convenience over direct commands. It lists accepted Mitigators with their declared object and value parameters, plus registered raw actions as one-action plans. Execution uses the ordinary PlanExecutor under existing controller RBAC and always-on executor checks. The menu adds no selection ledger, quiescence, provenance, health-reader or credential-delta preconditions. Reports return what ran, per-action results, value provenance and any error to the same responder session, with up to five rounds per incident. Pick from the menu when an option fits; if it fails, read the report and pick another or fix it directly. Current unexplained objects have controller-checked removal options; typed failure reasons guide recovery. EnsureDatabaseUser accepts env or namespace-local ConfigMap key credential references, optionally narrowed to one literal assignment. Only the executor resolves values into private stdin; plans, receipts and recordings retain references. Direct Secret keys require a separate security review. Author Mitigators as self-contained repairs with declared parameters and specific failure context. Intermediate reports are not independent incident outcomes or program trust credit. prior_response_progress retains successful receipts and blockers from failed episodes of the same open problem. admission_blocked names the webhook/configuration that prevents rollout; applied writes remain.

## Controller verification and command reports

Plain verification returns the cached controller verdict immediately. Waiting returns on stable independent closure, a new or reactivated finding, or timeout, without running detectors. Fresh detector evaluation remains the detect path. After verified closure, incident_verified adds an informational timestamp and message to every normal result; reads and reports continue. New mutations receive a typed incident_verified rejection receipt.

Mutating commands always store complete per-action results, evidence, program runs, reports and receipts under $SDO_SESSION_SCRATCH/sdo-reports/<incident>/<sequence>-<command>.json. Their compact output states action and incident verdicts separately, compares controller cached finding sets by fingerprint and evidence (fixed/new/unchanged), and prints the file path and generated schema. A failed action line names the failure reason, exit code and first error line.

```json
{
  "actions": "array of {command,summary,program_runs,report,option_reports}: complete independent option outputs/receipts; overlapping writes refused",
  "findings": "array of {summary,status,detector_id,fingerprint,primary_resource,evidence}: current findings with full evidence",
  "fixed": "array of Finding (findings[] shape): absent since the before snapshot",
  "new": "array of Finding (findings[] shape): new fingerprint or changed evidence; possible regression",
  "option_reports": "array of {status,rounds,attempt_id}: typed per-option execution reports in selection order",
```

## Tool reply budget

A reflection tool reply over 8192 bytes is saved whole to a file; the reply names its size and path with a short partial head. Search or extract from that file; the head is not the whole result.

## authoring_reference

Read shipped authoring references: a section index, or one section by heading or declaration.

The full topic text is saved once to the file named in the reply; search
that file instead of re-reading the reference. The sdk topic starts with
the SDK card: exact signatures grouped by fault, one line each.

## create_corpus

Create a positive replay fixture from recorded session observations or optional captures.

Pass observations to use the snapshot and primitive replies already in
the responder session; include accepted_json for source-reading plans.
Missing controller captures do not block this mode. Without observations,
copy the selected available capture and peer context. repair_receipt_ids
names the outcome's hand repairs these programs encode; their exact
RepairReceipt entries are added for you. Replay snapshots and verdicts are informational.

## evidence_inventory

List capture digests, counts and a few resource names, bound to the accepted outcome.

Recorded method counts cover the whole file. Use recordings_index to locate
primitive calls without reading result payloads. Full immutable evidence
remains available through capture_fields and to
independent validation. Read relevant fields rather than entire captures.

## capture_fields

Read captured resource fields or primitive recordings on demand.

Fields are dotted paths; list indices are numeric (spec.containers.0.image).
Null collections are empty. Results are paginated; the shared reply cap
saves large complete pages to a session file. Extract relevant fields
from that file. Missing fields are null, never evidence that a primitive succeeded.

## recordings_index

Index primitive calls by original position, phase, method, bound object and error.

Filters search the entire recording. next_offset marks incomplete pages;
a truncated page does not establish that a primitive was unrecorded.
Empty recorded phases mean open. phase_index locates the call within that
phase's capture_fields page. Error excerpts report omitted characters.
open_phase selects the protected recording file, including its fixed observations.
Result payloads remain available through capture_fields.

## check_memory

Run the complete memory check and wait for final diagnostics (at most 300s).

Supply the typed decision fields directly; this tool writes the result
JSON outside the authored tree. Return the same decision and logical IDs.
It first gofmt-formats Go files changed under .sdo/.
Legacy decision_path files are also supported. One call waits for final
diagnostics. Compile/import/format/provenance checks remain required;
replay verdicts are information and never block saving. The broker repeats the check.
