# Generated fastloop workers

Fastloop defaults to `fastloop/agent_registrations` for toy runs. Both registrations
launch `fastloop.generated_worker`, which reads the typed live task, generates a
separate responder or reflection script into the writable tool exchange, and
launches the ordinary production worker through `agent_script`. The production
worker and provider parser own typed publication and model-session metadata.

Responder scripts execute planning, live drift investigation, source restoration,
and verified attribution. Reflection scripts author programs and captured corpora,
then invoke the shared Go memory validator. Reference Go programs remain benchmark
assets. No custom responder or reflector implementation remains in the adapter.

Replay executes the same generators and stand-in provider using captured command
transport. Generated scripts and incident captures stay outside the repository.
Tests retain synthetic source, drift, policy, provenance, tool-transport and broker
acceptance scenarios, with explicit expected script results.
