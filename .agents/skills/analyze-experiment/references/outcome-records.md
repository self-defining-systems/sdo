# Outcome and program evidence

## Outcome records

Phase-1 program memory stores responder-owned Go `diagnose.go`, optional `mitigate.go`, and tests beside judgement guidance in `.sdo/playbooks/<fault-class>/`. Shared helpers are under `.sdo/lib/<package>/`; labeled replay cases are under `.sdo/corpus/<case>/` with `open.json`, `fixed.json`, `healthy.json`, `recordings.json`, and `labels.json`. Reflection authors these files directly in its isolated checkout. The isolated broker validator and local `memory check` share compilation, generalization and rename-invariance replay; a program's presence alone does not show runtime use or a mitigation. Correlate any later program-use claim with controller outcomes and accepted commits.

For every new captured corpus case, including one for an existing program, `open.json` comes from one of the controller's application-namespace captures: `open@detect.json` or the first-mutation `open@pre-apply.json` (older runs may also have `open@settle.json`). See [capture boundaries](capture-boundaries.md) for best-effort capture and evidence-gap semantics. Reflection selects a pre-mitigation capture phase and copies its bytes directly into the five corpus files, authoring labels with capture digests, bindings, peer bindings, and root-cause IDs. The shared Go validator verifies those bytes against the private capture directory; `labels.json` records the selected `provenance.open_at`. Each open capture has an adjacent `open@<phase>-recordings.json` for ReadView primitive calls. `fixed.json` is captured after verified closure, and `healthy.json` reuses the fixed snapshot with a same-kind peer binding. Captures live privately at `.sdo-runtime/sessions/<first-32-hex-of-sha256(incident_id)>/corpus/` until session pruning. Inspect `labels.json` `provenance.incident_id`, `open_at`, `open_sha256`, and `fixed_sha256` against the selected phase file and fixed file, and confirm the reflection commit passed broker validation. Sensitive environment values and Kubernetes write metadata are removed; inline synthetic NoMatch cases remain supported. An agent-authored near miss must carry `no_match_program_ids` and `synthetic_no_match_reason`; do not count it as observed incident evidence. Older accepted corpus cases may predate capture provenance; treat their open/fixed/healthy JSON as author reconstructions, not independent evidence of generalization. Shared `validate.Check` compares every added captured case against the provisioned incident and capture directory; missing context is `program.capture-unavailable`, and mismatched or empty incident labels and modified capture bytes are `program.capture-provenance`. Self-reported hashes alone do not establish capture provenance. Every accepted case is immutable against the accepted base commit (`program.corpus-immutable`): snapshots, recordings, provenance, bindings and labels cannot be rewritten or deleted. This also protects legacy and synthetic cases; unchanged historical cases do not need the current incident's capture mount. New evidence requires a new case ID, and relabeling accepted evidence is unsupported. Changed Go source must already be gofmt formatted; publication preserves authored bytes.

Reflection may instead return `learning_decision=sdk_gap` with typed `sdk_gaps` entries (`fault_class`, missing `primitive`, `reason`, and `scratch_script`). These are in the durable native broker ledger's `reflection_decision`, joined to the immutable outcome by incident ID and `outcome_commit`; they record a proven check the current SDK could not express, not an accepted program or repair. An `updated` decision may also carry gaps for other faults. For an accepted program, inspect the reflection commit's playbook sources and corpus labels, then the broker validation evidence; the proposal or program self-check result alone does not prove acceptance.

An exhausted model-output correction returns a failed worker result. The native ledger then records `reflection_decision.learning_decision=failed` and `reflection_decision.error` with the validation reason, sets `reflection_processed=true`, and completes closure without a reflection commit. The already committed successful outcome remains the mitigation record. A repeated identical worker request is not evidence of three distinct learning attempts; check the worker result and broker ledger separately.

The logical outcome schema is `OutcomeRecord` in `sdo/contracts/proto/sdodev/contracts/v1alpha1/outcome.proto`. The active Go memory adapter stores one versioned JSON document per incident at `.sdo/outcomes/<sha256(incident_id)>.json`; its logical `Reader` lists and gets records by incident ID, while only the broker has `Writer` capability. Reflection tasks carry the accepted current and prior outcomes as typed protobuf records. The adapter can import a retired `.sdo/outcomes.jsonl` stream and removes that stream only after every record is accepted. Correlate incident IDs and outcome commit hashes with the native broker ledger and benchmark `production-receipt/v2`. Important fields include:

- `incident_id`, `source_commit`, `deployed_commit`;
- `drift_events` retain controller-observed refs, bounded old/source/new fields, manager/operation/time and `classification` (`fault` for a learned match, otherwise `unexplained`). Current ordinary responder results may return exact event assessments with legacy `investigation_verdict`, `investigation_reason` and `investigation_evidence` spelling. Go validates them against incident observations; a bug requires source contradiction plus relation or impact evidence. Only checked benign labels in accepted outcomes suppress the identical manager and current/source observation after restart/reset. Bug and unsure never suppress repeats. A benign no-op is `cleared_without_action`, with no mitigation/trust/learning credit. State retains bounded history, not investigator requests, verdicts or drift admission accounting. Health and every retained synthetic drift finding must clear; source errors, missing bindings and Unknown remain unresolved. Learned deletion needs explicit NoMatch per retained binding. Ordinary captures use the incident session's `open@detect` phase. Ownership adoption retains counts, managers and retry diagnostics. Historical runs may contain investigator state and a separate verdict ConfigMap; current releases remove both.
- detector history, findings, and final health-detector state;
- surfaced, inspected, confirmed, rejected, and applied playbooks;
- confirmed root causes. Newer results give each cause `evidence` (live items only: `detector-finding`, `synthetic-traffic`, `state-change`, or `live-observation`, each with `source` and `observation`), `explained_detectors` (detectors that must clear after the fix), and `static_context` (scripts, manifests, ConfigMap bodies, or notes that motivated the hypothesis but prove nothing). Older records have these empty;
- `classification`: current records use `failed` (responder failure, dispatch error or health or admitted-source-drift verification timeout), `cleared_without_action` (verified health with no accepted source repair and no successful repair action), or `success` (verified health and a repair). Successful outcomes alone are eligible for reflection and prior-outcome recall. Root-cause claims are no longer independently verified: current outcomes omit `diagnosis_verification`, and closures/state omit `observed_state_changes`/`incident_observed_changes`. Historical outcomes may contain those fields and the retired `partial`, `external_recovery`, `false_positive`, `false_negative` and `cancelled` classes; interpret them under their original policy rather than treating them as current success;
- repair and memory commits, plus structured live repair-action receipts; newer receipts carry `resources`, the objects each action mutated (older ones only a free-form `target`, parsed as `[namespace/]Kind/name` when possible);
- responder backend/model and transport-reported usage (`llm_calls`, `input_tokens`, `cache_read_input_tokens`, `cache_write_input_tokens`, `cache_write_1h_input_tokens`, `uncached_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `model_requests`, and `total_cost_usd` when the provider reports it). `cached_input_tokens` is the deprecated alias of cache reads; a record without `cache_read_input_tokens` predates agentshim 0.7, and on Claude its `cached_input_tokens` also counted cache writes (subtract `cache_write_input_tokens` to get reads);
- detected, dispatched, mitigated, verified, and completed timestamps.
- `program_tool_calls` (command, time, request and response JSON, error), `program_runs` (program ID, finding fingerprint, binding source, bindings, verdict, duration, program revision, optional `can_mitigate`), and `plan_applications` (application ID, program IDs, plan, applied/dry-run flags, verification, error, duration, rollback state, applied actions, timing and optional final-equivalence proof; rollback pre-images and patches are not durable outcome fields). `binding_source` is `finding`, `hint`, or `sweep`; sweep runs have no finding fingerprint. Older runs omit this field. `response_loops_used` counts apply batches; `response_loop_exhausted` marks an unresolved budget stop. `program_failure_signals` distinguishes a matching diagnosis after apply, residual detector findings, newly surfaced findings, and ad-hoc coverage gaps. Read the [program trust rules](fastloop-results.md#program-trust-evidence) before counting successes. Fast-path execution is opt-in; infer actual use from `resolution_path` and the native ledger.

Tool responses expose logical playbook IDs. The outcome keeps a structured summary with `truncated: true` when a full tool response would exceed 2 KiB. A clean `verify` omits the unrelated namespace sweep. For verified repairs, `timestamps.mitigated_at` is the latest successful repair completion no later than closure completion, falling back to responder completion when no valid completed repair receipt exists.

When a responder completes but health does not clear or admitted owned-field drift on a source-declared object in the incident namespace remains unresolved within the controller's verification window, the controller closes the incident with empty `final_detector_states`; the outcome is classified `failed`. Source-comparison errors also keep verification waiting. The outcome retains the admitted `findings` and `drift_events`; the closure's `incident_detector_states` records the latest firing or error evaluation. An image repair and clear readiness alone cannot establish success while admitted targetPort drift remains. Restoring the admitted fields to accepted source permits closure; unowned or undeclared changes are not new blockers. Late drift can attach after dispatch to the same incident, so inspect the final closure/outcome rather than only the frozen worker request. Historical dev closures before FX2 checked health alone; do not retrospectively assume they ruled out admitted drift. No outcome schema or classification names changed.

Useful queries for the active per-incident outcome documents:

```bash
jq -s 'map({incident_id, classification, repair_commit, memory_commit})' .sdo/outcomes/*.json
jq -s 'group_by(.classification) | map({classification: .[0].classification, count: length})' .sdo/outcomes/*.json
```

The filename is a hash, not an incident ID. For a historical checkout containing JSONL, inspect its accepted Git revision and import state before combining counts.

Program-run `can_mitigate` records whether the compiled registry has a mitigator; `false` means diagnosis-only, and an absent field on older evidence means unknown. It does not establish trust, plan validity or replay support. Responder prompts omit NoMatch runs and report `omitted_no_match_program_runs`; durable requests, outcomes and captures retain the full runs.

Go may add deterministic `repeat-<digest>` corpus cases through normal reflection validation and broker publication without dispatching an LLM, when every cause/matched binding has verified plan-equivalent repair evidence. Corpus-only decisions are `updated` with no changed playbook IDs; no README annotation is needed. Trust consumes only the covered instances in the controller-owned, pre-commit eligibility result; adding corpus files supplies no independent credit. Runtime dependency revisions now exclude `_test.go` as well as Markdown; older runs can reset trust on test-only changes. A cleared bound program with another explicit open resource finding is not a failed application; global health is independently required for the final outcome. Older traces can contain false `diagnosis_clear_detectors_firing` and application-failure signals from composite incidents, which prevent trust even when each bound apply response is NoMatch.

OutcomeRecord.reflection_eligibility version 1 durably stores Go-owned typed items before the outcome commit. ReflectionRequest.cause_work carries those items grouped by the exact confirmed_root_causes indices/resources; unassigned_work contains ungrouped observations. Covered items require verified equivalent repair; fixed_capture_match items preserve exact fixed snapshots as required NoMatch corpus cases. No other question grants credit. PlanApplication.final_equivalence_verified must be affirmatively true for covered eligibility; false or absent means unproven. An absent fixed verdict is also a question. Fixed negative corpus cases have only no_match_program_ids and provenance naming the SDK fixed-negative phase; they cannot earn origin credit. Validation retries retain the responder session and typed work/diagnostics.

Current reflection workers can materialize positive cases through the typed `create_corpus` tool. It copies the controller open/fixed/recording bytes and derives phase values and SHA-256 provenance; it does not grant acceptance. The broker still compares the proposed bytes independently. The typed `check_memory` input is unwrapped ReflectionResult fields; the final model reply retains the session envelope with `reflection` populated and `incident_result` null. The generated worker guide is `sdo/skills/sdo-memory/references/runtime.md`; generated program API documentation is `sdo/skills/sdo-playbook-authoring/references/program-sdk.md`.

Reflection evidence browsing is a bounded projection only: inventory and field pages carry the accepted outcome commit, incident ID and capture digests. Oversized page items require narrower field selection, not a conclusion that evidence is absent. Full captures and the committed outcome remain authoritative. Prompt memory inventories excerpt accepted text and omit script bodies; accepted files remain in the proposal checkout.

`reflection_evidence_gap_count` on the native ledger and first-party incident row counts distinct confirmed
resource/phase pairs with no observation in the complete protected recordings. Historical absence is unknown,
not zero. Recorded errors count as present calls, not as successful evidence. `decline_reason=evidence_gap`
identifies an actual no-change decline; Go rejects it when no gap was flagged. A nonzero presence-gap count
alone does not establish blocked learning, and already-proven covered repairs still skip the model.

Evidence-gap items and the distinct resource/phase count are part of the same pre-commit `reflection_eligibility` result. The native ledger projects that saved count for receipts; it does not reclassify recordings during reflection retries. Historical outcomes without an indexed count remain unknown, rather than zero.


Structured plan effects (XV1): `SetField.value_from_source` resolves at the incident-bound accepted revision; `document_format` and `document_path` identify one JSON/YAML entry within a bracketed ConfigMap data key. These are action intent, not proof of health. Structured executor effects require expiring controller-owned nonsecret provenance, a hard Secret-reference predicate, direct current field/UID checks, and strict informer barriers. Missing provenance, unwatched kinds and stalled observations remain refusal/unknown, never success. Safety authorization and preimages stay process-local; durable protobuf applications do not acquire mutation journals or replay authority.

Object lifecycle receipts add `PlanApplication.object_effects`: operation, ref, server UID, state (`not_applied`/`applied`/`unknown`), confirmed direct observation, and irreversibility. A delete includes an authorized nonsecret `deleted_pre_image` for inspection only; it is never a restart mutation journal or recreation authority. Create ownership requires its server UID receipt; an identical object after a lost create reply is still unknown. Successful API deletion without confirmed named absence is not verified repair. These effects report `skipped_unreplayable_effect` in corpus replay and earn no origin credit.

Plan application JSON patch receipts carry `Authorization`: `accepted-source` for structured source-only effects, `incident-named-delete` for individually named UID-pinned source-absent deletes, and `parameter` or `observed` for provenance-typed values on the inherited narrow SetField allowlist. A declared value matching source still records `accepted-source` when admitted through the structured source policy. These labels classify authority, not independent health verification or trust credit.


Plan applications now expose `action_reports`: each report names its action index, status (`prepared`,
`applied`, `refused`, or `unknown`), and value provenance. Source values retain `source_commit`, reference and
field path; observed values retain the invocation snapshot's `resource_version`, reference and path; scalar
parameters retain their declaration name. Reports contain no resolved value. Exec reports only `exit_code`,
never stdout/stderr; a refusal or unknown outcome is not verification evidence. DeletePod records an
irreversible named UID effect without a Pod body or recreation authority. ScaleWorkload verifies replicas
through a direct read. Captured snapshots preserve resourceVersions for observed-value provenance while
stripping UID and write metadata. Program bindings now separate `objects` and scalar `values`; object-only
historical corpus bindings remain readable. These receipts describe evidence, never restart mutation journals.
