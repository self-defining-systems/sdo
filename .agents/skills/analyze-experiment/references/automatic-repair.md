# Automatic repair evidence


Fast path and recorded-actions now default on, trust threshold is 1, and a broker-validated program revision preserves prior success credit. A real fast-path failure still resets trust. Selection attempts one trusted program/binding by distinct covered findings, then stable program ID/bindings order. Uncovered findings, ambiguous alternatives and unexplained drift no longer cause pre-apply refusal. Whole-incident verification still decides closure; failure rolls back reversible writes before sequential responder dispatch. Historical skip-reason strings remain readable but removed coverage/revision/policy gates are no longer emitted.

Plan patch Authorization now reports value provenance (`accepted-source`, `parameter`, `observed`, `incident-namespace`) rather than a source/reviewed-fixture grant. Historical `reviewed-fixture` and `incident-named-delete` receipts retain their original meaning. Outcome and result field layouts are unchanged; controller-config policy tags 72–74 are retired and reserved. No policy-loaded startup event or `SDO_PLAN_SOURCE_POLICY_FILE` is expected. Defaults: 10 loops, 5 validation retries, 5-minute verification, menu on unless explicitly disabled.

Current fast-path receipts may contain completed Go settlement with version-1 reflection eligibility, rather than the retired `trusted program fast path` skip string. Acceptance still requires matching programs, applied verified plans, no rollback or failure signal, no responder Job, acknowledged commits and complete accepted reflection.
