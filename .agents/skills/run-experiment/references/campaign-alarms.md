# Campaign alarms, scheduling rules, driver discipline and timings

Thresholds and habits that turn the in-principle minimum into checks. Each alarm is a watcher check that flags the arm and names an owner, never just a note.

## Alarm per stage

These tighten the general rule that actual above 2× the minimum is a bug.

| stage | alarm |
| --- | --- |
| one-off setup | longer than one problem's minimum |
| claim, reset, gate with a warm pool | above about 2 min |
| fresh lane build | above 2× its reference timing |
| agent-active share of a run | below about 25% of wall time |
| dependency chain | above 1.5× its minimum |
| lane utilization with work queued | below about 70% |

## Scheduling rules

Each rule ends with the principled fix, so the class cannot recur.

- **Start every serial prerequisite at launch, in parallel.** A second app's baseline or pool build that waits for the first app's runs leaves its lanes idle. Fix: the plan lists every prerequisite with its minimum, and the driver starts them all at launch, within the build limits below; a prerequisite not started by launch is a plan defect.
- **Give pool builds and run builds separate, load-gated limits.** One shared `max_builds` lets pool builds starve run builds, and the reverse. Fix: set each limit separately, gate each on its host's load threshold (kept in the host state file), and have the watcher report every idle lane's blocking reason (build limit, load gate, disk floor, no ready pool lane).
- **Calibrate `min_free` to footprint.** Measure one lane's disk footprint first. Fix: the preflight sets `min_free` to footprint × planned lanes plus the host's reserved headroom and refuses a smaller value.
- **Settle must not wait on pre-inject readiness** (for example a store baseline's promotion). A wait that answers idle once and then restarts never gives the two consecutive idle answers settle needs, so post-fault runs hit the cap and turn invalid. Fix: after the inject, settle treats a readiness-only answer as idle; a test covers the restart case.
- **Compare image IDs, not tags, across every lane host.** A mutable tag can point at different builds on different hosts. Fix: preflight compares IDs per host and deploys by immutable tag or digest.
- **An app without request metrics needs no telemetry decision.** The request-metrics detector reports an operation whose entry service has no `entries` record as not applicable (an `O3.detector-coverage` note), so a provided plan passes onboarding with the metrics source on; use one telemetry setting across arms. If `O4.detectors` still fails on `request-metrics.not-instrumented`, the map declares an `entries` record the app does not serve: fix the map, not the profile.
- **Gate run scheduling on a golden pool lane, with no fresh-build path.** Claimants added together with their pool fall back to fresh builds (26-30 min instead of a 1-2 min claim), and a claimant already holding a lane skips any external gate (a pass 2 paid 20 min after the gate was live). Fix: a runner `claim_only` mode in which a claimant never builds fresh and waits for a pool lane; the pool builds one golden lane per host first; the watcher flags any run on a fresh build.
- **Bound a skipped check.** A check skipped on a ledger-proven lane still took 4 min (it waited on the operator's idle answer). Fix: a ledger-proven lane goes swap to run in under a minute, the skipped check's remaining wait is bounded (about 30 s), and a test covers the swap-to-run path.
- **Give each pool its own build slots.** Pool builds share `max_builds` with each other and with run builds, so the first-sorted pool starves the second (hotel waited behind three GitLab pool builds). Fix: separate, load-gated limits per pool and for run builds; the watcher names the blocking limit for every idle lane.
- **Report claimants waiting per pool in every digest.** Idle lanes with queued claimants are invisible otherwise. Fix: a status line "claimants waiting for pool P: N, ready lanes: M" per pool, and an alarm when N > 0 while a lane is free for 10 minutes.
- **Read the grader's reason before rerunning an invalid cell.** A validity check can be an artifact of the operator under test: fuzzops' `hurts` stops at the operator's first action, so an operator that detected in 16 s made a harmful fault read `no_harm`. Fix: the grader judges at least the fault's admitted onset span or reports `undetermined`; until then record the cell with its evidence instead of rerunning.
- **A step waiting for cores must not hold a build slot.** A hotel build waited 24 min on "4 cores asked, 0 free" behind a GitLab lane while holding the host's only build slot, and the step kept the cpuset it started with, so widening the host's block did not help it. Fix: a core-waiting step does not count as a build, a free kept lane releases its cores when another step waits for them, preflight checks each host's cpuset fits its apps' lane shapes, and an alarm fires on any step with no phase change after 5 minutes.
- **Count whole-core capacity before adding clusters.** The allocator hands out only cores whose every SMT thread is in the host's block, so the CPUs above another experiment's pinned range held 23 whole cores, not the 64 CPUs listed; extra clusters became ghost lanes waiting for cores. Fix: the inventory refuses more clusters than the whole cores fit for the planned lane shapes, and reports the count.
- **Recover on a missing cluster is a no-op.** Killing a build before its cluster existed sent the lane `down` with "fault still active", because recover read the missing cluster as a failed undo; a manual `lane reset` could also be lost to a concurrent manager write. Fix: recover with no cluster or namespace reports nothing active, and a reset is applied by the manager, not overwritten by it.
- **No golden snapshot while an incident is open, or after a long idle wait.** A pool lane's golden copy was taken with an incident open, and the incident leaked into every claimed run on that lane. Fix: the snapshot refuses unless the operator answered idle for a quiet span just before it, and a claimed run that finds an incident it did not cause fails its gate by name.
- **Never retag a shared host image tag.** Retagging spokane1's `fuzzops/hotel:dev` to our build changed what other threads' lanes would deploy. Fix: packs deploy by an immutable, content-derived tag or digest (fuzzops #106), preflight compares layers across hosts, and a run uses its own tag; restore any shared tag you changed.
- **Warm the Go build cache into the golden copy.** A closing turn's first `go build` took 3 min 47 s cold against 2.5 s warm, inside settle on every claimed run. Fix: the golden copy (and a swap's new tree, `benchmarks/devswap/warm.py`) carries a warm Go build cache for the agent workspace, so no run pays a cold compile.
- **Bind each hold pool only to its own hosts.** The first-sorted pool takes every lane it may use, even ones meant for another app. Fix: list the allowed hosts per pool in the spec, and have the preflight refuse a lane assigned to a pool whose host list excludes it.

- **Check a series offline before its first live attempt.** Twelve findings of the GitLab commit series each cost a 20-minute lane build and a run; the missing migration Job (a render the plan did not name) would have shown in seconds. Fix: run `python -m benchmarks.commit_series.preflight --series S --baseline B [--kubeconfig LANE]` first: plan covers every workload of every release, migration Job present, the real replayer pushes every commit onto the baseline's memory, every image resolves, a server-side dry-run applies. Run a series on a free kind lane until it is clean before spending an EKS lane on it.
- **A test double for a lane read comes from the real read path.** The commit-series test lane keyed holds to the pushed sha, which hid that the adapter read a removed ConfigMap and that SDO's hold names its own commit on top of the push (every held position waited the whole verdict bound). Fix: test the lane class itself through a fake `kubectl`, with the ConfigMap shape SDO writes.
- **Set a position's verdict bound from the series' measured time, not a guess.** `verdict_s: 1500` against a 251-399 s reference made each missed verdict cost 25 minutes of lane time, and `plan remove` does not stop a run already on the lane: it ends at its own bound. Fix: bound = about 3x the reference per release; remove a plan before its lane is built, or accept the run's bound.
- **A workload that records its own incident wait tells settle to wait only for work in flight.** A series position waits (bounded) for the incident it opened and records it; settle waiting again to the run cap made the position `capped` and broke the sequence. Fix: the workload leaves `settle-work-only.json` in the lane directory and the subject's `idle` answers as a teardown's does.

- **Read a row's `valid` together with its `evidence_incomplete` stamp, and a failure's first cause, not its prefix.** `not injected: X` is every failure before the injection (here: a missing credentials Secret, a node agent, an SDO pod that stayed Pending), so a probe read as "the selector fault is not injected" while the fault was never reached; and a row with no verified evidence copy printed `NOT GRADED` yet the lane record called it valid. Fix: the lanes workload record is invalid when fastloop's evidence gate stamped the row, and the failure text names the pod's scheduling reason and events instead of a bare timeout.
- **A stub arm cannot judge a fault no restore-from-source undoes.** The scripted worker only restores what the accepted source describes, so a cluster-scoped fault (an admission webhook outage) ends with the oracle failing and, by design, the lane taken down as `fault still active`; that says nothing about the injector or about vcluster. Fix: validate such problems with a real agent arm and judge the stub row by injection and detection only.
- **A copy verified by size must not verify a file the copy rewrites.** `copy_interval` rewrites `index.jsonl` (Python spacing, only the copied units) while the Go sink writes it compact, so the size check refused every copy whose index differed in length. Fix: verify the rewritten index by its records.

- **Rehearse a SREGym plan on a local vcluster host before an EKS lane.** The same plan, adapters and lane facts run for free on a kind host cluster (`eks.local_kind`, docs/eks.md "A local kind host cluster"): 13 items on 6 lanes showed in two hours what EKS probes showed one bug at a time (lock release, lane health gate, unit kill mode, stub reach, unsupported fault classes). Only ECR, the node agent, Karpenter, EBS and the VPC CNI need AWS. Fix: `lanes host adopt` the local host, add the whole plan with `parallel` at least the item count (a smaller cap leaves lanes idle while items wait), read every failure of the round, then confirm on EKS.
- **A stub plan holds only faults the scripted worker restores from source.** It repairs Services and NetworkPolicies; a Deployment fault (readiness probe, `dnsPolicy`) or a webhook ends `fault-still-active` and takes the lane Down (a human `lane reset` brings it back), after an incident that never closes (its row now ends at the spec cap as `incident_not_closed`, evidence copied, instead of waiting for a commit that cannot arrive). Fix: put those problems on a real-agent arm and judge a stub row of them by injection and detection only; never let them retry (the second identical failure parks the item anyway).
- **A wait for an acknowledgement needs the bound of what can produce it.** The outcome-commit wait ran to the 4.4 h reflection deadline for an incident whose alerts never cleared (a closure no controller can acknowledge); the row deadline added in #1768 only killed it from outside, unnamed. Fix: fastloop `--closure-bound` (lanes passes the spec cap): an incident still open that long after injection ends the row `incident_not_closed`, the grade kept and no closing turn waited for.
- **A fault matrix flag is a claim until a row injected it.** `fastloop_supported: true` for `cumulative_admission_webhook_timeout_hotel_reservation` ended `not injected: per-fault tracking unsupported`. Fix: check each matrix row's class against the fastloop tracker offline before it enters a plan; `gen_plan.py` refuses any id whose matrix `fastloop_supported` is false.
- **Rehearse every position of a series, not its first.** The kind rehearsal passed positions 1 and 2 and crash-looped the controller at position 3: SDO rebuilds its controller for a judge refresh about three minutes after each head deploy, and only the push that landed inside that window met the refresh on an undeployed head (positions 1 and 2 landed outside it by luck). Fix: a series counts as rehearsed when every position produced a graded verdict on a free lane after the last fix, and a fix to the controller needs its own full rehearsal.
- **Read the controller's last log before waiting out a `controller pod not Ready` release.** A crash-looping controller held the lane's release idle wait for 21 minutes (until its Job gave up) while the cause sat in the pod's last log line. Fix: when a row ends `lane lost` or a release reports the controller not Ready, read the newest `sdo-controller-run-*` log first and fix the cause; the next plan cannot use the lane until the wait ends.
- **A lane's residue check judges against what the row start restores, not against the build's snapshot.** Every SREGym row ended `cluster-scoped residue` (the operator's own namespace, `sdo-admin-*` and `sdo-prometheus-*` roles and bindings) and the lane's cluster was made anew: +5 min cluster-up and +11 min app and prepare per row, no warm lane. The workload installs the operator at each row start (after tier 1 wipes the last install), so it is never in the build's baseline. Fix: the workload names what its row start removes and recreates (`app-reset owned`, `benchmarks/lanes/docs/contract.md`) and lanes excuses exactly that; a fault's webhook or ClusterRole is still residue. A workload that installs anything per row must answer it, and a row's `residue` interval with the same detail on every row is this bug, not a fault.
- **A shared helper's new wait or gate must be opt-in by the caller that reads its evidence, and every caller must be walked before the merge.** Two commit-series fixes cost three EKS runs. #1791 made the verdict evaluation wait for an existing-records step that had not run yet: head deploys (which never read that evidence) paid about seven extra 90 s evaluations (`deploy_seconds` 892 instead of 400), and the judge refresh of an already-onboarded app still failed O4 after the longer wait, because the evidence is onboarding-only. Fix: only the caller that reads the evidence waits (`awaitVerdict` gate option), and a refresh is not gated on onboarding evidence at all. Before a fix to a shared helper lands, list its callers and say for each whether it reads what the change waits for; after it lands, read `deploy_seconds` of the first position before letting the rest of a run go on.
- **A fix for a Kubernetes field-ownership class is validated against the live managedFields of every Invalid object, not the first error.** The first fix released exactly-shared paths (volumes) and passed; the same head still held on `lifecycle.preStop: must specify a handler type`, where helm owned a sibling path (`exec` markers) the deployer did not: a 30 min kind run and a pool rebuild. Fix: the test and the fix cover every path equal to, above or below a deployer-owned path, and the envtest case is built from the real chart's `kubectl get -o yaml --show-managed-fields` for each rejected object.
- **A plan's `isolation` field must equal the run's recorded isolation mode, or be omitted.** An EKS rep with valid records was failed by the plan (`source-mismatch: run isolation eks, the plan requires two-way`) and a retry started: 45 min of lane time. Fix: read the `isolation` mode of a first record from the lane kind and copy it, or leave the field out; do not copy it from a plan written for another lane kind.
- **A pool or snapshot path must run its prerequisites on the host before the pool is queued.** A kind pool built for 18 min, then failed at the golden-copy snapshot because `FUZZOPS_BIN` was set on one host and not the other. Fix: check every env the snapshot, reset and verify-start verbs read on each host (`hosts.yaml`) with a one-line probe before the build starts.
- **Never `git stash` in a repository with worktrees.** Stashes are repository-global: `git stash pop` in one worktree applied another worktree's stash. Fix: commit to a scratch branch, or copy the files, instead.
- **Check for a live driver before taking over, and say you exist.** Two drivers ran the GitLab commit series for two hours (one after the other account's limit lifted, one after a takeover brief), each logging "no other series agents", building duplicate pools and adding plans on the same pin. Fix: at takeover read `lanes plan status` and the state file's newest entries and its modification time (a plan or entry newer than the dead driver's last line means someone is live), append a "takeover" line first, and message the owning thread before touching any plan or lane that is not in your own log.
- **The control plane of an EKS experiment runs on the manager's machine; read its load before and during a run.** Every step (harness, `go run`, kubectl, aws, fastloop) runs there, and at a load average of 7,800-15,000 (other tenants' workloads) calls timed out inside rows (`SREGym fault description failed (timeout)`, `lane memory inventory unavailable ... TimeoutExpired`, `lane lost`), rows failed `not-injected` and their timings were not real. Fix: `lanes preflight` fails an eks host whose manager machine is over `eks.max_load5_per_core` (default 4) and the manager starts no build or run above it; if it trips, move the manager to a quiet host instead of trusting timings from an overloaded one.

## Driver discipline

- **Keep the driver resumable:** chaining logic in a script with state on disk, never in one agent turn. Write decisions and a status line (every 30 minutes) to `NOTES.md` in the run directory so a replacement can take over after a rate limit. Spread agents across accounts.
- **Wait by bounded foreground polling** (about every 5 minutes), never by ending a turn on a monitor.
- **Every harness wait has a deadline and logs progress.** A wait that ends silently (for example for a seeded controller Pod that never becomes ready) holds a lane for an hour while the driver counts it as running. Fix: bound the wait, end the row with a named error so the driver requeues it, and give the driver a stall rule that covers every wait.
- **A run step must end when its experiment is cancelled or its row outlives the spec.** A row sat 83 min after its last log line (the harness waiting for the controller's closure acknowledgement, silent, bound only by the 1 h reflection deadline), `plan remove --cancel` did not kill it (the plan backend removed the experiment with run steps left to finish) and the manager's kill signalled only the step's own process group, not the adapter's. Fix: the lanes step hands the spec's cap and ready_timeout to the adapter, which kills the run's whole process tree at ready_timeout + cap + closeout and ends the row invalid naming the wait it was in (every polling wait names itself in the log each minute and in `current-wait.json`); `--cancel` kills run steps; the manager's kill signals the step's whole session (TERM, then KILL). Do not end a stuck step by hand: read `current-wait.json` in the run's `exec/` directory.
- **A removed plan can still hold and bill a lane.** A lane `held` for incomplete evidence stays held after its plan is removed: an EKS lane billed 4 h 40 min that way, and the next plan sat queued behind it and was removed without running. Fix: after removing a plan, and after adding one, read `lanes status` within 10 minutes. Free every lane the removed plan holds through the manager: write `operator/evidence-waiver.json` and rebuild the manifest (`python -m benchmarks.fuzzops.cellevidence manifest RUN_DIR`), then `lane release`. A plan still unplaced after 10 minutes needs its blocking lane named.
- **Stop a plan's work with `lanes plan remove NAME`, never `lanes remove EXPERIMENT`.** Removing an experiment counts as a failed attempt, so the plan queues an `-x1` retry and starts a fresh lane build. `plan remove` deletes the plan's experiment directories, records included: copy any record you need first, or pass `--keep`.
- **Set the run cap from the run's own minimum, not a generous default.** Settle and the release's idle wait are bounded by the cap. An incident nothing will close (escalated, stub agent) cost one cap in settle and up to another in the release (2 h each at `cap: 120m`).
- **A step bound equal to the wait inside it is no bound.** A release waited for an incident that stayed open (the idle gate before the operator is deleted) for exactly the 2 h step bound and was killed before its cluster delete ran, so the lane billed on. Fix: a step's bound is its longest inner wait plus the work after it (release: cap + 1 h), and every wait logs what it still waits for every 5 minutes.
- **A free lane prepared on a checkout the pins no longer list must still be deleted.** Re-pinning left such a lane unreleasable ("release refused: no checkout", one line every 15 s, nodes billing for hours). Fix: a cluster delete needs no workload checkout; after a re-pin read `lanes status` for lanes still billing on old pins.
- **Count failures per problem, not per lane, and park on the second identical one.** A problem that fails the same way on every lane is requeued forever when only lane failures are counted (one failed 17 times at 30 minutes each).
- **A step that has no experiment must still get its workload's env.** A lane's recover step ran after its plan was cancelled, the manager took the workload from the (gone) experiment, and the undo failed `SREGYM_LANES_ENV is not set`: the lane was reset, then went down and its cluster was deleted. Fix: a step's env follows the workload resolved for the step (from the lane's prepared state when there is no experiment); every workload call goes through one constructor, and a test enumerates the step kinds and verbs.
- **Put only problems SDO pages on by itself into a learning arm.** A harness-paged incident (grade `page_source: fallback`, for example `network_policy_block` on hotel) closes `cleared_without_action`: its alert set was clear before the agent's first change, so the closing turn learns nothing (`cleared_without_action_no_learning`) and p2 is a second cold run. Check `page_source` and `playbooks_learned` of the first real row of each problem before it enters p1/p2 arms; the principled fix is classifying a harness-paged incident by the repair that preceded the verified clear.
- **Probing one bug at a time is how EKS cost a day: conformance first.** Nine probes found nine bugs of four classes (step env missing, wait without deadline, node-local path, host-global name); each cost a lane build. Fix: `tests/unit/benchmarks/sregym/lanes/test_adapter_conformance.py` runs every adapter verb and action (derived from the contract doc and the dispatch table) with the environment `lanes` gives a step (parsed from `step.go`), and fails in seconds when a verb reads an undeclared variable, does not name a missing one, runs a command before checking its inputs, or runs a subprocess without a timeout. A new verb or action without a case fails. Run it, and a static sweep of the substrate's path for every verb (the four classes, per file and line), before the first probe of a new substrate.
- **A model or resource the lane kind cannot serve must be refused by name at the first step that knows both.** An Opus row on a vcluster lane (no node to hold its session pool) died at row start, after the lane was built and the fault injected. Fix: the adapter's `app-up` and `run` refuse it from the operator file and `BENCH_LANE_VIRTUAL` before anything starts, fastloop's row start does the same, and the pool may live on NFS (`SDO_OPUS_POOL_NFS_SERVER`); a new lane-kind limit gets a refusal and a conformance case, not a late failure.
- **Rehearse the real-agent plan through the manager on the local vcluster host too, and pin only merged commits.** The first manager-driven local round of the real-agent arms (3 items x p1/cold/p2, Sonnet, about $4) passed end to end (build, run, closing turn, memory export, artifact edge, seeded p2 deterministic at $0, grade, release) and still found three lane-state classes: a row refused before its injection (a lane built for other images) answered `run active` unknown, so the platform took a clean lane Down for a human reset; a kept lane reused by a spec naming other images skipped `up` and failed at its first row; a build the manager cancelled mid-`app up` left the app half installed on a cluster that build had made, and the next `up` there fails for ever. A pin that merged an open PR's head over an older main also lacked the image-check fix and failed every row at once. Fix: `run` writes its fault verdict clear before any check that can refuse, the reused-lane `app up` fails the build on other images (the platform then makes the cluster anew), a killed build marks the lane for recreation, and plan pins are commits on origin/main.
- **A lane's nodes are its own: never let a chart default reserve disk on them.** An astronomy row failed `sdo-repository-sync Pod did not become ready ... Insufficient ephemeral-storage` and then `controller has no ready owned Pod`, and passed on the third try, on 100 GiB nodes with almost nothing written. The vcluster chart's LimitRange gives every container `requests.ephemeral-storage: 3Gi`; the host scheduler counts those requests against a node's 89 GiB allocatable, so 32 app containers plus the observability stack put one of the lane's two nodes at 87 Gi (97 %) while the other sat at 48 Gi, and the SDO claims pinned to the full node (`SDO_VOLUME_NODE`) could not schedule. Local kind lanes never showed it (a node's disk is the machine's). Fix: the lane values null the chart's ephemeral-storage default (`eks-vcluster.sh`, `vcluster-lane.sh`, red-first tests); a not-ready controller Pod now names its phase, scheduling condition and events (`inspect-existing`). Diagnose any `Insufficient <resource>` on a lane with `kubectl describe node` on the host (`<lane>.host` kubeconfig, nodes labelled `sdo-lane=<lane>`: Allocated resources), not the lane's own API.
- **Stage by path in an SDO worktree, never `git commit -a`.** A worktree whose SREGym submodule checkout is behind the pin shows `third_party/sregym` modified, and `-a` commits the old pin: the static check "SREGym submodule pin" fails the PR. Fix: `git add <paths>`; `git diff origin/main --stat -- third_party` before the push; after a rebase run `scripts/init_test_prereqs.py`.
- **A path only a live run takes must be rehearsed through the manager, never with hand-set env.** A real-agent plan's lanes failed `app up` (`docker image inspect sdo-controller:fastloop` returned 1): the adapter chooses the agent's images from the operator file (`BENCH_OPERATOR`), but a lanes build ran its first verbs (identity, check-pack, app down/up) before it wrote the file, so they got the host's defaults. The local end-to-end run had exported `BENCH_OPERATOR` by hand and passed. Fix: lanes writes the operator file before the step's first workload call and `laneEnv` names it for every call of a build, run or release whenever the spec has an operator block (`BENCH_OPERATOR_BLOCK=1` says it does; the adapter refuses a call that lost the file by name); a test enumerates the build paths (fresh app, rewind, swap, new cluster) and the verbs each calls. Rehearse a new live-only path with a plan on a local lane through the manager, and read the env a verb got from the step's log, not from your shell.

- **Rehearse a live-only path through the manager, never with hand-set environment.** The real-agent mode passed a hand-driven local run and then failed on its first manager-driven row twice: the build's `app-up` had no operator file (the images never reached `fastloop up`), and the run compared the lane's pushed ECR digest references with the spec's image tags. Fix: the rehearsal runs the plan through a (local) lanes manager and the same host environment, and a stage's identity check compares what was *asked for* (recorded at `up`), never what the provider delivered.
- **Set a plan's `parallel` to the lane count when lanes are unlabelled.** The manager assigns lanes to released nodes in experiment NAME order, so only `parallel` (below the node count) makes the plan's item order the release order; with per-app lane labels `parallel` = node count was the workaround, which let one app's rows fill every lane. Put the longest p1 -> p2 chains first and set `parallel` to the number of lanes.
- **Release idle EKS lanes of a finished round yourself.** `idle_timeout` is host-wide `wanted()`: another plan's pool kept ten idle nodes billing for 47 minutes after the stub round. Fix: after a round, `lane release` every lane that is not in the next plan's images or pin, and read `awsq.sh` against the ledger.

- **`lanes add FILE --dry-run` is not a dry run.** The flag set is shared by every verb, so `--dry-run` (a flag of `plan add`) parsed on `add` and was ignored: three pool experiments of 18 lane builds were added, 16 lanes billed $6.4/h for 35 minutes with no row running. Fix: every verb refuses the flags of other verbs (`unknown flag --dry-run`); to check a plan use `lanes plan add FILE --dry-run`, to check a single spec read it with `lanes preflight`. After any `add` or `plan add`, read `lanes status` within two minutes.
- **A host-wide limit you change must be checked against what the host recorded, before any lane is built.** `FASTLOOP_HOST_REDEPLOYS` went from 8 to 18 while the shared lock directory's `redeploy.capacity` still said 8; the guard fired at each lane's first redeploy, after 18 clusters and 36 nodes existed, and every build failed. Fix: `app-up check-pack` (the first call of a build) refuses the mismatch before any cluster exists and names the file to delete when no lane uses the host. When you change such a value, delete the recorded file while the host is idle, and bring ONE lane up before scaling to N.
- **A failure line must lead with the cause.** `lane status` showed the head of a 2,300-character reason, which began with git's detached-HEAD advice; the real error (a ValueError naming the capacity) was 40 lines later. Fix: a failed call's reason carries its last three output lines (the whole tail stays in the step result and the log). When a lane fails, read the step's `runner.log` before anything else; two failures of the same build are a stop signal, not a retry.
- **A build must never be offered a lane the manager will refuse.** `freeLane` took the first free lane that holds its cores; one lane whose cluster was already gone (kubeconfig left, API unreachable, so gated "no new steps on it") was always that lane, its start was refused, the pass ended, and 20 lanes with no cluster sat "its build could not start" behind it (the 1-lane test pool never built). Fix: a gated lane is not a candidate, and a Gone lane's earlier unreachable reading is cleared. A lane left with a stale kubeconfig is released through the manager (`lane release`).
- **A lane that holds another app must be recreated, and a free lane that holds the app must be taken first.** With any lane allowed to run any app the first free lane by name was taken, so a hotel build landed on an astronomy lane, failed (namespace mismatch), then rebuilt. Fix (#1800): prefer the lane that holds the app; recreate up front otherwise.
- **The host's system node group has to follow the lane count.** It holds every vcluster control plane (about six per m6i.xlarge) but `up` pinned it to one node (maximum two). Fix (#1811): one node per six lanes, never lowered under running lanes. The real EC2 limit was 300 vCPU, not the 88 in `hosts.yaml`: read Service Quotas (`L-1216C47A`) before sizing a plan.
- **A pool lane's first claimant is fast; its successor must not claim a fresh pool lane.** A p2 that may claim (`claim_only: false`) takes a ready pool lane instead of reusing its p1's lane (and its reseed). Pause the pools once their lanes are claimed.
- **Every row, the first on a lane too, must recover at its end when rows reseed.** The first row of a lane deferred its recovery to a next-row wipe that a warm row never runs, so every second row fell back at `inspect` (#1817: with `SREGYM_LANES_RESEED=1` every row passes `--end-of-row-recovery`).
- **Do not `pkill -f` or `pgrep -f` a pattern your own shell command contains.** `pkill -f` killed the shell that ran it (exit 144) and a `until ! pgrep -f script.sh` loop matched itself and never ended. Use the pid of what you started.
- **A new local vcluster host needs `lanes host adopt HOST`** before any lane is built; read the manager's `serve.log` a minute after starting it (9 minutes were polled on "its host cluster lvc-host is not adopted").
- **Stamp logs from `TZ=America/Los_Angeles date`**, not by subtracting 8 h in your head (three entries were an hour late).
- **A PR branch cut long ago is tested merged with main.** #1805 failed a ratchet that landed after it was cut and its author had finished: rebase before opening and re-check `gh pr checks` once the queue accepts it.
